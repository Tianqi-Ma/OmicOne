## 1. 底层设计

### 发现的问题
| 严重度 | 问题 | 后果 |
|---|---|---|
| Critical | 18 处直接覆盖 `rv$obj`，没有任何"上游变了、下游作废"的机制 | 重跑归一化后，聚类、标志基因还显示旧结果并标为"已完成"；换一份数据后，各模块还在展示上一份数据的图表 |
| Critical | QC、去双细胞重跑时，在已过滤的数据上再过滤 | 实测 2700 → 2599 → 2584，细胞越删越多 |
| Major | 复现日志只追加不替换；单细胞和 WES 共用一份日志 | 导出的脚本会把 QC 执行两次；WES 没有自己的脚本 |
| Major | 单细胞步骤表在两个仓库各写一份，共享 helper 定义在壳层文件里 | 不同模型改一边漏一边，就是 `scstudio_theme()` 那种 bug 的来源 |
| Major | 统计结果被写回共享的 `rv$clinical`（单细胞和 WES 都有） | 队列在不同流程之间越用越少，分析集被上游悄悄裁剪 |
| Minor | scop 封装和通用绘图混在两个文件里，其中 7 个封装已经没人调用 | API 漂移无处可查 |

### 做了什么
- **新增 `R/fct_state.R`**：
  - 步骤表里每一步声明 `deps`；某一步重跑后，依赖它且已完成的下游步骤标为"过期"，导航显示琥珀色，页面顶部出提示条。
  - 新导入开启新批次（epoch），只清空该组学的状态、日志和模块结果，另一个组学不受影响。
  - QC 和去双细胞通过 `step_input()` 从固定的输入重跑，不会再在已过滤的数据上过滤。
- **共享注册表 `R/steps_sc.R`**：单细胞步骤只定义一次，两边仓库共用。
- **`tools/sync_mirror.sh`**：共享代码只在 OmicOne 改，用这个脚本同步到 scStudio（包名自动替换）。
- **分层更清晰**：`fct_compute.R`（Seurat 计算）/ `fct_scop.R`（scop 等外部引擎）/ `utils_inputs.R`（控件 helper）。
- **对象级约定写进 `obj@misc`**：当前降维、当前聚类分辨率、轨迹列，下游统一从这里读，不再靠猜。

## 2. 分析逻辑（按领域列出主要问题）

下面只列 Critical 和代表性的 Major，完整清单见各模块提交前的审计记录。表中问题均已修复。

### 单细胞上游
| 问题 | 修复 |
|---|---|
| scDblFinder 没按样本跑：多样本合并后期望双细胞率按总细胞数线性放大（4 万细胞时先验约 32%），还会在样本之间模拟出物理上不存在的双细胞 | 传 `samples=` 并设 seed；界面增加样本列选择 |
| SCT 之后 reduce 又跑了 ScaleData，Pearson 残差被覆盖，SCT 等于白做 | SCT 时沿用其 HVG 与残差 |
| CCA/RPCA 的 `integrated.dr` 下游根本选不到；选"none"也去不掉之前的 Harmony | 统一管理降维选择；整合预览做前后对比，并计算批次混合熵 |
| 默认的 Leiden 依赖 leidenbase 却没检查；k 控件没有生效；多分辨率时最后一个悄悄成为下游分组 | 自动识别可用后端；k 生效；分辨率由用户显式选定 |
| 标志基因 Top-N 只按 LFC 排序，实测 53.6% 不显著 | 先按 `p_val_adj < 0.05` 过滤 |
| SCE / v4 整合对象 / 多层 / 多模态 h5 导入后在 QC 一步就挂 | `standardize_sc_object()` 统一成 RNA assay |
| 预览图与文案不符：归一化只画原始深度、QC 文案说有小提琴图但没画、Markers 文案说点图实际是条形图 | 按文案补画；归一化改成前后对比，实测 rho 从 0.99 降到 0.10 |

### 单细胞下游
| 问题 | 修复 |
|---|---|
| 富集 / GSEA 必然报错：参数名不对，DE 结果 slot 不存在；ORA 背景是整个注释库；GSEA 只用显著基因排序 | 按 scop 0.9.2 重写；背景改为实际检验过的基因；GSEA 对全部检验基因排序 |
| RNA 速率必然报错，而且 neighbors 是在 2D UMAP 上算的 | 显式指定 PCA / UMAP；运行前检查 spliced / unspliced |
| 6 种轨迹方法只有 Slingshot 能跑，而且是在 UMAP 上拟合；Monocle3 会弹出交互窗口 | 各方法按自己的参数指定起点；Slingshot 改在 PCA / Harmony 上拟合 |
| CellChat 只调了 `createCellChat`，却标记为完成；LIANA 的图声称是"显著网络"，实际是未筛选的计数 | CellChat 跑完整流程；LIANA 做共识聚合并按阈值筛选 |
| copykat 把低置信度的非整倍体细胞判为"正常"，小鼠数据用的是人类基因组 | 分出恶性 / 正常 / 未定，另写置信度列；按样本、按物种运行 |

### 生存分析（用户最关心的两点）
| 问题 | 修复 |
|---|---|
| "最优切点"的 p 值未校正就画在 KM 图上，零假设下假阳性率实测 31% | 附上校正切点选择的 p 值（maxstat 或 Lausen–Schumacher 近似），模拟验证假阳性率回到约 5%；标注"探索性" |
| 没有 per-patient 机制：重复 ID 不检查；按样本列计算组成；不能先筛细胞子集 | 重复 ID 报错；新增病人层面组成聚合（细胞子集、分母、最少细胞数）；顺序固定为"先定分析集、后算切点" |
| 三分位遇到并列值时整组塌缩；分组后只剩一组也不提示 | 明确报错 |
| 上一次选的事件编码残留，导致所有事件变成 0 | 只在需要时才读取该控件 |
| 没有 HR、没有 PH 检验、没有小样本提示；图注声称有 CI 带和风险表，实际没画 | 加 CI 带、风险表、HR（95% CI）、每 SD 的连续 HR、cox.zph、多因素模型与 EPV 检查、小样本警告 |

| 问题 | 修复 |
|---|---|
| 生存分析丢掉了 MAF 里没有突变记录的测序样本（LAML：182 人，实际应为 188 人），野生型组系统性缺人 | 默认按野生型计入；ID 统一化；可按患者聚合 |

## 3. 建议新增的分析模块（按对转化研究的价值排序）

已经做了的：病人层面聚合、连续变量 Cox、切点校正、FDR 统一。下面是**尚未实现**的：

1. **Pseudobulk 差异表达**（按患者聚合后用 DESeq2 / edgeR）。比较应答与非应答这类患者分组时，可以避免细胞级 Wilcoxon 的伪重复。
2. **差异丰度分析**：propeller / miloR / scCODA。scop 已经导出了 RunPropeller、RunMilo，接入成本低。
3. **环境 RNA 校正**：SoupX / decontX，或导入 CellBender 的输出。实体瘤消化样本几乎都需要。
4. **外部验证接口**：把单细胞签名投到 TCGA-ESCA、GSE53625、IMvigor210 上做生存分析。单细胞队列太小，不足以单独支撑生存结论。
5. **WES：变异过滤与质控**：PASS、深度、VAF、gnomAD、FFPE / OxoG 伪影、超突变标记。目前 TMB、签名、驱动分析都直接用原始 MAF。
6. **WES：dNdScv**，能同时找出抑癌基因和癌基因，补上 oncodrive 漏掉的散在截短型驱动。
7. **WES：OncoKB 注释**，只把致癌变异算作突变型；**CNV / GISTIC 导入**，oncoplot 同时显示扩增与缺失。
8. **TMB 与 ICI 疗效关联**：连续 TMB、ROC、治疗臂 × TMB 交互项。
9. **WES 报告与导出步骤**：日志已经按组学分开，复用单细胞的报告和导出模块即可。
10. **长任务异步化**：scVelo、CellChat、copykat 用 `shiny::ExtendedTask`，运行时界面不会卡死。
